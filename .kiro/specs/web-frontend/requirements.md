# Web 前端 UI — 需求文档

## 背景

hrids-agent 目前提供 Gateway 模式（HTTP REST + WebSocket），已具备完整的多会话并发接口。
但缺少可视化前端，非技术用户无法直接使用，也无法在浏览器中与 agent 交互。

本 Spec 目标：为 hrids-agent 开发一个现代化的 Web 前端，连接 Gateway 服务，提供类 ChatGPT 的对话体验，同时暴露 agent 特有的工具执行、权限管理、会话切换等能力。

---

## 整体导航结构

```
左侧导航栏（全局）          中间区域（会话上下文）      右侧面板（会话上下文）
─────────────────          ──────────────────────      ──────────────────────
[+] 新会话                  对话消息列表                Tab: 任务产物 | 工作目录
[🧠] 专家                   流式输出 + 工具卡片
[⚡] 技能                   输入栏 + 状态栏
[🤖] 自动化
─────────────────
会话列表
  session-1 ●
  session-2 ○
  ...
```

- **新会话**：创建新的 agent 会话
- **专家**：专家模式入口（后续迭代）
- **技能**：浏览和调用已安装的 skill
- **自动化**：全局任务（`todos.json`）+ 定时任务（`crons.json`），跨会话持久化
- **右侧面板**：仅在有活跃会话时显示，内容随会话切换

## 用户故事

### US-1 基础对话
**作为**用户，**我希望**在浏览器中与 agent 进行多轮对话，**以便**不需要打开终端就能使用 agent。

**验收标准：**
- 可以在输入框中输入消息并发送
- agent 的回复以流式方式逐字显示（text_delta 事件）
- 支持 Markdown 渲染（代码块、列表、加粗等）
- 发送中显示加载状态，完成后恢复输入

### US-2 工具执行可视化
**作为**用户，**我希望**看到 agent 正在调用哪些工具、执行进度和结果，**以便**了解 agent 的工作过程。

**验收标准：**
- 工具调用开始时显示工具名称和参数摘要（tool_start）
- 工具执行中显示实时日志（tool_log，可折叠）
- 工具完成后显示结果摘要（tool_end），成功/失败用不同颜色区分
- 工具卡片可展开查看完整输入/输出

### US-3 权限管理交互
**作为**用户，**我希望**在 agent 请求执行写操作时收到提示并决定是否允许，**以便**保持对 agent 行为的控制。

**验收标准：**
- 收到 `permission_request` 时弹出确认对话框
- 显示工具名称、操作描述、是否只读
- 提供"允许"/"拒绝"按钮，点击后发送 `permission_reply`
- 超时（5分钟）前必须响应，否则自动拒绝并提示用户

### US-4 会话管理
**作为**用户，**我希望**创建、切换和删除多个会话，**以便**同时处理不同的任务。

**验收标准：**
- 左侧导航栏下方显示所有活跃会话列表（状态：ready / busy / stopped）
- 点击"新会话"按钮创建会话（可选：指定模型、工作目录）
- 可以切换到已有会话（恢复历史消息）
- 可以删除会话（需二次确认）
- 会话状态实时更新（busy 时显示动画）

### US-5 ask_user 交互
**作为**用户，**我希望**当 agent 需要我提供信息时能够回答，**以便**agent 可以继续执行任务。

**验收标准：**
- 收到 `ask_user` 事件时，在对话中显示问题和选项（若有）
- 输入框切换为回答模式，发送后触发 `user_reply`
- 若有预设选项，显示为可点击按钮

### US-6 成本与用量显示
**作为**用户，**我希望**看到每次对话消耗的 token 数量和费用，**以便**控制使用成本。

**验收标准：**
- 每条 assistant 消息下方显示 token 用量（输入/输出）
- 状态栏显示当前会话累计费用（USD）
- 超出预算时显示警告（budget_exceeded 事件）

### US-7 中止任务
**作为**用户，**我希望**在 agent 执行过程中随时中止任务，**以便**纠正错误的指令。

**验收标准：**
- 执行中显示"中止"按钮
- 点击后发送 `abort` 消息
- 中止后显示提示，恢复输入框

### US-8 连接配置
**作为**用户，**我希望**配置 Gateway 地址和认证 Token，**以便**连接到不同的 agent 服务。

**验收标准：**
- 首次访问或连接失败时显示配置页面
- 可输入 Gateway URL（默认 `http://localhost:3282`）和 Bearer Token
- 配置保存到 localStorage
- 连接成功后进入主界面，失败时显示错误信息

### US-9 右侧面板：任务产物 & 工作目录
**作为**用户，**我希望**在右侧面板通过 Tab 切换查看当前会话的「任务产物」和「工作目录」，**以便**了解 agent 的执行进度和文件变化。

**验收标准：**

**通用：**
- 右侧面板顶部有两个 Tab：`任务产物` | `工作目录`
- 面板可通过 `[›]` 按钮整体折叠，折叠后对话区域自动扩展
- 仅在有活跃会话时显示，无会话时隐藏
- 会话切换时，两个 Tab 的内容自动切换到新会话的数据

**任务产物 Tab（会话级隔离）：**
- 显示当前会话的 todo 列表，来源：`GET /sessions/:id/todos`
- agent 在当前会话调用 `todo_write` 时，通过 WS `todos_updated` 事件实时刷新
- 每条任务显示：状态图标（`○` 待处理 / `▸` 进行中 / `✓` 已完成）、优先级标签、任务内容
- 已完成任务显示删除线，进行中任务高亮
- 任务列表为空时显示"暂无任务产物"提示
- **不显示全局任务**（全局任务在"自动化"页面管理）

**工作目录 Tab（会话级隔离）：**
- 显示当前会话 `cwd` 下的目录和文件，支持逐级展开/折叠（懒加载）
- 目录和文件用不同图标区分，隐藏文件（`.` 开头）默认折叠
- 点击文件名，在对话输入框中插入 `@文件路径` 引用
- 点击刷新按钮可重新加载目录内容
- `cwd_changed` 事件触发时自动刷新文件树根目录

### US-10 自动化页面（全局）
**作为**用户，**我希望**在"自动化"页面统一管理全局任务和定时任务，**以便**规划跨会话的长期工作和自动触发任务。

**验收标准：**

**全局任务区块：**
- 显示 `~/.hrids-agent/todos.json` 中的任务列表（`GET /todos`）
- 每条任务显示状态图标、优先级标签、任务内容
- 提供手动刷新按钮

**定时任务区块：**
- 显示 `~/.hrids-agent/crons.json` 中的所有定时任务（`GET /crons`）
- 每条定时任务显示：启用状态开关、cron 表达式、描述、下次执行时间、上次执行时间
- 支持启用/禁用切换（调用 `PUT /crons/:id/toggle`）
- 支持删除定时任务（需二次确认，调用 `DELETE /crons/:id`）
- 任务列表为空时显示"暂无定时任务"提示

### US-11 技能页面
**作为**用户，**我希望**在"技能"页面浏览已安装的 skill，**以便**了解 agent 具备哪些专项能力。

**验收标准：**
- 显示所有已安装的 skill 列表（`GET /skills`）
- 每条 skill 显示：名称、描述、来源（内置/用户/项目）
- 点击 skill 可查看完整的 prompt 内容

## 非功能需求

| 类别 | 要求 |
|------|------|
| **技术栈** | React 18 + TypeScript + Vite，不引入重型框架 |
| **样式** | Tailwind CSS，深色主题为主，支持浅色切换 |
| **状态管理** | Zustand（轻量，无 Redux 样板代码） |
| **Markdown** | react-markdown + remark-gfm + react-syntax-highlighter |
| **WebSocket** | 原生 WebSocket API，封装重连逻辑 |
| **构建产物** | 静态文件，可直接由 Gateway 的 Express 服务托管 |
| **浏览器支持** | 现代浏览器（Chrome/Firefox/Safari 最新两个版本） |
| **响应式** | 支持桌面端（≥1024px），移动端基础可用 |
| **性能** | 首屏加载 < 2s（本地），长对话（>100条消息）不卡顿 |

## 约束与边界

- **不做**：用户账号系统、多用户权限隔离（由 Gateway Token 承担）
- **不做**：文件上传/下载 UI（agent 通过工具直接操作文件系统）
- **不做**：移动端原生 App
- **前端独立部署**：前端作为独立的 Vite 项目，构建后静态文件由 Gateway Express 托管，或独立部署
- **后端改动（最小化）：**
  - `TodoWriteTool` 改为会话级存储（有 sessionId 时写 `sessions/<id>/todos.json`，无则写全局）
  - Gateway 新增 `GET /todos` 接口（全局任务，只读展示）
  - Gateway 新增 `GET /sessions/:id/todos` 接口（会话任务产物）
  - Gateway 新增 `GET /sessions/:id/files` 接口（文件树）
  - Gateway 新增 `GET /crons`、`PUT /crons/:id/toggle`、`DELETE /crons/:id` 接口（定时任务管理）
  - Gateway 新增 `GET /skills` 接口（技能列表）
  - WebSocket 新增 `todos_updated` 推送事件（仅会话任务变更时触发）
  - 其余接口不变
